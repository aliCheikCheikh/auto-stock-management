1. Rôle

Le StockMovement est le journal immuable du stock. Chaque mouvement enregistre une opération atomique : un produit, une quantité, un emplacement source et/ou destination, un utilisateur, une date.

Un mouvement est créé une seule fois, jamais modifié ni supprimé.

3. Attributs

Attribut Type Description

movementId

MovementId (Value Object)

Identifiant unique du mouvement.

productId

ProductId

Produit concerné par le mouvement.

sourceLocationId

LocationId? (nullable)

Emplacement d’où part la marchandise. null pour une ENTRY (la source est extérieure au système).

destinationLocationId

LocationId? (nullable)

Emplacement où arrive la marchandise. null pour une EXIT (la destination est extérieure au système — le client).

type

MovementType (Enum)

Type de mouvement : ENTRY, EXIT, ou TRANSFER.

quantity

int

Nombre d’unités déplacées. Toujours strictement positif.

performedBy

UserId

Utilisateur ayant effectué le mouvement.

occurredAt

DateTime

Date et heure du mouvement.

saleId

SaleId? (nullable)

Référence vers la vente qui a déclenché ce mouvement. Présent uniquement pour les mouvements de type EXIT liés à une vente.

4. Invariants

Invariant Description

Quantité > 0

Un mouvement porte toujours une quantité strictement positive.

Cohérence source/destination selon le type

  • ENTRY : sourceLocationId doit être null, destinationLocationId obligatoire

  • EXIT : sourceLocationId obligatoire, destinationLocationId doit être null

  • TRANSFER : les deux sont obligatoires, et ils doivent être différents

Immuabilité

Aucun setter, aucune méthode de modification. La seule opération possible est la création via les factory methods.

5. Factory Methods

Le StockMovement utilise des factory methods statiques plutôt qu’un constructeur ouvert. Chaque factory method encode les règles de validité pour son type de mouvement.

5.1. createEntry(productId, destinationId, quantity, userId)

Crée un mouvement d’entrée. Force sourceLocationId = null et type = ENTRY.

5.2. createExit(productId, sourceId, quantity, userId, saleId)

Crée un mouvement de sortie. Force destinationLocationId = null et type = EXIT. Le saleId est obligatoire pour une sortie liée à une vente.

5.3. createTransfer(productId, sourceId, destinationId, quantity, userId)

Crée un mouvement de transfert. Vérifie que sourceId ≠ destinationId et type = TRANSFER.

6. Pourquoi un agrégat séparé

Raison Explication

Cycle de vie indépendant

Les mouvements sont consultés, filtrés et agrégés indépendamment des produits (historique du jour, mouvements par date, etc.).

Taille d’agrégat

Un Product avec des milliers de mouvements serait un agrégat obèse, violant le principe de petits agrégats.

Concurrence

Deux vendeurs peuvent créer des mouvements simultanément. Si tout est dans Product, un verrou inutile bloque l’agrégat entier.

Immuabilité

Le mouvement est créé et figé. Il n’a pas besoin des méthodes de modification d’un agrégat riche.

7. Requêtes typiques sur les mouvements

Ces requêtes sont gérées par le Repository (StockMovementRepository) au niveau infrastructure, pas par l’agrégat lui-même :

  • Mouvements d’aujourd’hui : findByDate(today)

  • Mouvements d’un produit : findByProductId(productId)

  • Mouvements d’un emplacement : findByLocationId(locationId)

  • Mouvements liés à une vente : findBySaleId(saleId)

  • Mouvements par plage de dates : findByDateRange(from, to)
