== Responsibility

A Domain Service contains business logic that does not naturally belong to a single aggregate, particularly operations involving several aggregates.
It is stateless and coordinates aggregates without replacing them.

== StockAllocationService

Distributes a sale request across available locations. For four filters, it might allocate three from the shop floor and one from backstock.

[plantuml]
----
@startuml
!theme plain
skinparam backgroundColor transparent
skinparam classAttributeIconSize 0

class StockAllocationService <<Domain Service>> {
  + allocate(productId : ProductId, requestedQty : int, shopId : ShopId) : List<AllocationResult>
}

class AllocationResult <<Value Object>> {
  - locationId : LocationId
  - quantity : int
}

StockAllocationService ..> StorageLocation : reads
StockAllocationService ..> AllocationResult : returns

@enduml
----

=== Allocation algorithm

. Load all `StorageLocation` instances for the `Shop`.
. Sort with `SHOP_FLOOR` before `BACKSTOCK`.
. At each location, allocate the smaller of the available and remaining requested quantities; append the allocation and decrease the remaining quantity.
. Throw `InsufficientStockException` if any requested quantity remains.
. Return the allocations.

For a request of four filters with three on the shop floor and seven in backstock, the result is `[(shopFloor, 3), (backstock, 1)]`.

This service calculates and returns allocations. The Application Service creates the `Sale` and `StockMovement` records; `StorageLocation` changes its own stock levels. Allocation itself performs no persistence.

== ReceivingService

Coordinates receipt of goods according to the user's chosen distribution, for example 50 filters split into 15 on the shop floor and 35 in backstock.
It creates movements and updates stock levels.

[plantuml]
----
@startuml
!theme plain
skinparam backgroundColor transparent
skinparam classAttributeIconSize 0

class ReceivingService <<Domain Service>> {
  + receive(entries : List<ReceivingEntry>) : List<StockMovement>
}

class ReceivingEntry <<Value Object>> {
  - productId : ProductId
  - locationId : LocationId
  - quantity : int
}

ReceivingService ..> StorageLocation : updates
ReceivingService ..> StockMovement : creates
ReceivingService ..> ReceivingEntry : receives

@enduml
----

=== Flow

. For each `ReceivingEntry`, load the location by `locationId`, call `increaseStock(productId, quantity)` and create an entry movement with `StockMovement.createEntry(productId, locationId, quantity, userId)`.
. Check whether global stock has risen above the threshold; if so, emit `StockReplenished`.
. Return the created movements.

Unlike automatic sale allocation, receiving records the user's distribution choices and adds units to stock.

== Application service boundary

The Domain Services remain in the domain layer. The Application Service coordinates the complete operation from the application layer:

----
