== Context and scenario

The seller replenishes the shop floor from backstock. Only the distribution changes; global stock remains unchanged.
In this example, the shop floor has one filter and the seller transfers ten from backstock.

== Created movement

A single `StockMovement` uses `type = TRANSFER`, the oil-filter `productId`, backstock as its source, the shop floor as its destination, quantity 10, the seller's `performedBy` identifier, and `saleId = null`.

== Errors

If backstock has five filters and the requested transfer is ten, `StorageLocation.decreaseStock(productId, 10)` throws `InsufficientStockException`.
The transfer is rejected, with no movement created and no stock changed.

`StockMovement.createTransfer(productId, shopFloorId, shopFloorId, 10, userId)` throws `InvalidMovementException` because source and destination must differ.
The factory method protects this invariant.

== Events and manual confirmation

`ShopFloorLow` can be emitted if the source is a `SHOP_FLOOR` location and its quantity falls below `lowStockIndicator` after transfer.
A transfer never emits `LowStockAlert` or `StockReplenished`, because global stock is unchanged.

Transfers are manual. `ShopFloorLow` can prompt the seller with a dashboard notification such as "Oil filter: one unit on the shop floor; 15 available in backstock". The seller decides whether to transfer stock.
