== Definition

A value object is defined by its attributes rather than an identity. Two value objects are equal when all their attributes match.
They are immutable: changes return new instances.

== Typed identifiers

Typed value objects replace bare `String` or `int` identifiers. This prevents passing a `ProductId` where a `LocationId` is expected, makes signatures such as `findByProductId(ProductId id)` explicit, and encapsulates identifier generation.

[cols="1,1"]
|===
| Identifier | Used by

| `ProductId`
| `Product`, `StockLevel`, `StockMovement`, `SaleLineItem`

| `CategoryId`
| `Category`, `Product`

| `LocationId`
| `StorageLocation`, `StockMovement`

| `MovementId`
| `StockMovement`

| `SaleId`
| `Sale`, `StockMovement`

| `UserId`
| `User`, `StockMovement`, `Sale`

| `ShopId`
| `Shop`, `StorageLocation`
|===

== Money

`Money` contains an `amount` (`BigDecimal`, avoiding floating-point rounding errors) and a `currency` (`Currency`, allowing multiple currencies).

* `add(other)` adds amounts and throws if currencies differ.
* `multiply(quantity)` calculates amounts such as a sale line total.
* `isPositive()` tests whether the amount is strictly positive.

== StockLevel

`StockLevel` exists only inside its parent `StorageLocation` and shares its lifecycle.
See xref:aggregate-storage-location.adoc[StorageLocation].

== AllocationResult

Returned by `StockAllocationService`: a `LocationId locationId` and strictly positive `int quantity` describe how many units to take from a location.
See xref:domain-services.adoc[Domain Services].

For four filters, the returned `List<AllocationResult>` might be `[(shopFloor, 3), (backstock, 1)]`.
`SellProductUseCase` iterates over the list to call `storageLocation.decreaseStock()` and create one `StockMovement.createExit()` per location.

== ReceivingEntry

Input to `ReceivingService`: `ProductId productId`, `LocationId locationId` and strictly positive `int quantity` describe which product and how many units to place at a location.

For 50 filters split into 15 on the shop floor and 35 in backstock, the Application Service creates two entries:
`[(filterId, shopFloorId, 15), (filterId, backstockId, 35)]`.

== Enums

[cols="1,1"]
|===
| Enum value | Meaning

| `MovementType.ENTRY`
| Goods enter the system from a supplier; source is `null`.

| `MovementType.EXIT`
| Goods leave the system through a sale; destination is `null`.

| `MovementType.TRANSFER`
| Internal movement requiring source and destination.

| `LocationType.SHOP_FLOOR`
| Sales area, used first for allocation.

| `LocationType.BACKSTOCK`
| Rear storage, used after shop-floor stock.

| `UserRole.OWNER`
| Shop owner with full access.

| `UserRole.SELLER`
| Seller with operational access to sales and movements.
|===
