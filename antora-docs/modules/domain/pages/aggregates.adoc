== Definition

An aggregate is a group of domain objects treated as a unit for data changes.
Its aggregate root is the only entry point for mutations.

== Design principles

Each aggregate protects a minimal set of invariants. Objects belong together when they must change consistently together.
Aggregates reference one another by identifier: a `StockMovement` stores a `ProductId`, not an embedded `Product`.

In this design, each aggregate forms a transaction boundary: one aggregate changes per transaction, with domain events providing eventual consistency between aggregates.

== Design decisions

[cols="1,1"]
|===
| Decision | Reason

| `StockLevel` belongs to `StorageLocation`
| Stock is a property of a physical location. The location protects the nonnegative quantity invariant.

| `StockMovement` is separate from `Product`
| Movements have their own lifecycle and queries; embedding them would make the product aggregate grow indefinitely.

| `SaleLineItem` belongs to `Sale`
| Line items are created and read with their sale and have no independent existence.

| `Category` is independent
| It has its own identity and can evolve independently of products.

| `Shop` is included from the start
| A `shopId` on `StorageLocation` supports future multi-shop use.
|===
