== Context and scenario

The owner receives goods and chooses how to distribute them between the shop floor and backstock.
In this example, 50 oil filters are received: 15 on the shop floor and 35 in backstock.

== Sequence diagram

[plantuml]
----
@startuml
!theme plain
skinparam backgroundColor transparent

actor Owner as V
participant "ReceiveStockUseCase" as AS
participant "ProductRepository" as PR
participant "ReceivingService" as RS
participant "StorageLocation\n(Shop floor)" as SLM
participant "StorageLocation\n(Backstock)" as SLR
participant "StorageLocation\nRepository" as SLR_R
participant "StockMovement\nRepository" as SMR
participant "EventPublisher" as EP

V -> AS : execute(ReceiveStockCommand)\n(reference, [(shopFloor,15), (backstock,35)])
activate AS

== 1. Find or create the product ==

AS -> PR : findByReference(reference)
alt unknown product
  AS -> AS : requires newProductInfo
  AS -> PR : save(new Product(...))
end
PR --> AS : product

== 2. Delegate to the Domain Service ==

AS -> AS : map TargetLocation → ReceivingEntry
AS -> RS : receive(entries, userId)
activate RS

loop for each ReceivingEntry
  RS -> SLR_R : findById(locationId)
  RS -> SLM : increaseStock(productId, qty)
  SLM -> SLM : StockLevel += qty
  RS -> SLR_R : save(location)
  RS -> RS : StockMovement.createEntry(\n  productId, locId, qty, userId)
end

RS --> AS : [movement1, movement2]
deactivate RS

== 3. Persist movements ==

AS -> SMR : saveAll(movements)

== 4. Events ==

AS -> AS : events += StockReceived(productId, totalReceived,\n  locationBreakdown, userId)
AS -> AS : globalStock = sum(findAll().stockLevel(productId))
alt globalStock > minimumGlobalThreshold
  AS -> AS : events += StockReplenished(productId, name,\n  globalStock, threshold)
end

AS -> EP : publish(events)

AS --> V : void
deactivate AS

@enduml
----

== Created movements

Both movements use `type = ENTRY`, the oil-filter `productId`, a null external source, the owner's `performedBy` identifier and `saleId = null`.
The first movement sends 15 units to the shop floor; the second sends 35 to backstock.

== New product

When the product is not yet in the catalog:

[plantuml]
----
@startuml
!theme plain
skinparam backgroundColor transparent

actor Seller as V
participant "Application Service" as AS
participant "Product\nRepository" as PR

V -> AS : receive(productInfo, allocation)
activate AS

AS -> PR : findByReference(ref)
PR --> AS : null (not found)

AS -> AS : Create Product(\n  name, reference,\n  categoryId, unitPrice,\n  threshold)
AS -> PR : save(newProduct)

AS -> AS : Continue the normal\nreceiving flow

deactivate AS

@enduml
----

Creating the product and recording the receipt affect two different aggregates. The Application Service coordinates them.

== Events

* `StockReceived`: always emitted after a successful receipt.
* `StockReplenished`: emitted if global stock rises above `minimumGlobalThreshold`.
