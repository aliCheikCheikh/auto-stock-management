== Invariants par agrégat

=== Product

[cols="1,2,1"]
|===
| Règle | Description | Conséquence si violée

| R-PROD-01
| Le nom ne peut pas être vide
| Rejet de la création/modification

| R-PROD-02
| La référence est unique dans le catalogue
| Rejet de la création (vérifié au Repository)

| R-PROD-03
| Le seuil d'alerte global ≥ 0
| Rejet de la modification

| R-PROD-04
| Le prix unitaire > 0
| Rejet de la création/modification
|===

=== StorageLocation

[cols="1,2,1"]
|===
| Règle | Description | Conséquence si violée

| R-LOC-01
| **La quantité d'un StockLevel ≥ 0**
| `InsufficientStockException`

| R-LOC-02
| Le libellé ne peut pas être vide
| Rejet de la création

| R-LOC-03
| L'indicateur magasin bas ≥ 0
| Rejet de la modification
|===

=== StockMovement

[cols="1,2,1"]
|===
| Règle | Description | Conséquence si violée

| R-MOV-01
| La quantité > 0
| Rejet de la création

| R-MOV-02
| ENTRY : source = null, destination obligatoire
| `InvalidMovementException`

| R-MOV-03
| EXIT : source obligatoire, destination = null
| `InvalidMovementException`

| R-MOV-04
| TRANSFER : source et destination obligatoires et différentes
| `InvalidMovementException`

| R-MOV-05
| Immuabilité : aucune modification après création
| Pas de setter exposé
|===

=== Sale

[cols="1,2,1"]
|===
| Règle | Description | Conséquence si violée

| R-SALE-01
| Au moins un SaleLineItem
| Rejet de la création

| R-SALE-02
| Quantité de chaque ligne > 0
| Rejet de l'ajout de ligne

| R-SALE-03
| Prix unitaire de chaque ligne > 0
| Rejet de l'ajout de ligne

| R-SALE-04
| totalAmount = somme des lineTotal
| Recalculé automatiquement
|===

== Règles métier transverses

=== Allocation de stock (vente)

[cols="1,3"]
|===
| Règle | Description

| R-ALLOC-01
| Le magasin (`SHOP_FLOOR`) est toujours priorisé avant la réserve (`BACKSTOCK`).

| R-ALLOC-02
| Si le stock total (tous emplacements) est insuffisant, la vente est refusée.

| R-ALLOC-03
| L'allocation est proposée au vendeur, qui confirme avant exécution.
|===

=== Approvisionnement

[cols="1,3"]
|===
| Règle | Description

| R-RECV-01
| La répartition entre emplacements est décidée par l'utilisateur, pas par le système.

| R-RECV-02
| Chaque entrée génère autant de mouvements que d'emplacements concernés.

| R-RECV-03
| Si un produit n'existe pas, il doit être créé avant l'enregistrement de l'entrée.
|===

=== Alertes

[cols="1,3"]
|===
| Règle | Description

| R-ALERT-01
| L'alerte critique (`LowStockAlert`) se déclenche quand le stock global < `minimumGlobalThreshold`.

| R-ALERT-02
| L'indicateur opérationnel (`ShopFloorLow`) se déclenche quand le stock magasin < `lowStockIndicator`.

| R-ALERT-03
| L'alerte critique est désactivée quand le stock global repasse au-dessus du seuil (`StockReplenished`).
|===

== Premiers tests TDD à écrire

Les invariants ci-dessus sont les premiers candidats pour les tests unitaires.
Voici l'ordre recommandé :

[source]
----
1. StorageLocation
   - decreaseStock avec quantité suffisante → succès
   - decreaseStock qui ferait passer sous zéro → InsufficientStockException
   - increaseStock sur produit inexistant → crée le StockLevel

2. StockMovement
   - createEntry avec source non-null → InvalidMovementException
   - createExit avec destination non-null → InvalidMovementException
   - createTransfer avec source = destination → InvalidMovementException
   - quantité ≤ 0 → rejet

3. Sale
   - Sale sans SaleLineItem → rejet
   - totalAmount calculé correctement

4. StockAllocationService
   - allocation standard (magasin suffisant)
   - allocation mixte (magasin + réserve)
   - stock insuffisant → InsufficientStockException

5. Product
   - isGlobalStockBelowThreshold → true/false selon la quantité
----
